# Outils qui rendent une LISTE sans rien retirer de chaque enregistrement.
# Un outil NEUF ne doit jamais s'ajouter ici : déclare ce que ton défaut retire.
# Cette liste ne peut que DÉCROÎTRE — cf. tests/test_sorties_listes_projetees.py.
#
# La règle, par OUTIL : un outil servi qui expose un paramètre de pagination (`page`,
# `size`, `limit`, `cursor`, `page_size`, `per_page`, `offset`) rend une liste par
# construction. Il doit alors, soit exposer `fields` ou `full` (l'appelant peut
# projeter, et le défaut est la vue resserrée — ADR 0047), soit appeler une projection
# dans son propre corps (`output_projection`, `_shape(`, `summarize(`, `_project(`,
# `_slim…`). Sinon il est ici.
#
# Mesuré le 2026-09-10 sur le montage réel (`register_all`) : 508 outils servis,
# 169 paginants, 32 qui projettent par paramètre, 1 par appel dans son corps, et les
# 136 ci-dessous. Sur trois jours d'une org cliente en production, UN seul outil de
# liste pesait 68 % de tous les caractères servis : c'est ce qu'un défaut non
# resserré coûte à l'échelle, et c'est ce que #918 a dû corriger après coup.
#
# ⚠️ Ce que la règle NE mesure PAS, pour que personne ne lui fasse dire plus :
# - elle détecte une DÉCLARATION, pas un effet. Un `fields` qui ne retire rien passe.
#   Le poids réel se lit dans le journal (`tool_calls.result_size`,
#   `oto_org_monitoring op=summary`), pas ici ;
# - une projection faite dans un helper APPELÉ par l'outil, hors de son corps, se lit
#   comme de la dette. Le remède est d'appeler la projection depuis l'outil, ou
#   d'exposer `full` — pas d'ajouter un nom de marqueur à la liste du test ;
# - un outil qui rend une liste SANS paramètre de pagination (liste courte bornée par
#   l'amont) n'est pas vu.
#
